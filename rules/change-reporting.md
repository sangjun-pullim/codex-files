# Change reporting

Read before preparing a user-facing completion or stop report after code/configuration changes.
Workers relaying verification evidence read **돌린 검증**. AGENTS.md defines the report order;
this file defines the evidence and interpretation rules.

- **돌린 검증** — Report checks run against the final code, configuration, and inputs, plus still-valid results reused under Verification. For each command use `command → exit <code> | <verbatim tool summary>`, retaining summary lines with test run/pass/fail/skip counts. On failure, retain the summary and add the actual failure lines. Use `출력 없음` for no output; `요약 줄 없음` plus necessary raw output when there is no summary. Mark unavailable output or exit codes `확인 불가`. Include execution location and checked scope. Mark reused results `재사용` and explain their validity. Instruction comments and documents consumed by a checker are verification inputs. For checks without a command, report actions, inputs, and observations.
- **미검증 동작** — Identify changed behavior whose outcome on the final code, configuration, and inputs is not established by the tests or execution checks in **돌린 검증**. Exit 0 with zero tests or only skipped tests does not verify unexecuted behavior. Build, lint, and type-check success alone do not verify ordinary functionality; when changing those tools or their configuration, an execution that checks the changed processing outcome can verify that behavior. Report executed but failed checks as failures in **돌린 검증**, distinct from unexecuted or unknown results.
- **직접 고른 값** — List values chosen by the supervisor or workers that are absent from both the user's request and the impl-spec shown to the user, and are visible to callers, users, or stored data. Examples include defaults, limits, timeouts, ordering, error codes/messages, and public names. Include values the supervisor introduces in a worker handoff; exclude values copied unchanged from the request or presented impl-spec.
- **보고 근거** — Derive those three items by comparing the task's complete diff (committed, uncommitted, and new files), user request, presented impl-spec, worker handoffs, verification commands, actual output, checked scope, and code/configuration/inputs at execution time. Recover missing worker evidence from execution records; otherwise mark it `확인 불가`, never `없음`. After integration or follow-up edits, reassess result reuse and remaining verification against the final state.
